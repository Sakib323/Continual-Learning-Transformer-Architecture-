Architecture plan · continual learning from scratch

The Frequency-Graded Memory Stack

Which backbone to build on, which of the thirteen mechanisms to actually implement, and a design that ties four of them into one coherent system instead of a pile of patches. Two paths costed separately: pretraining 0.2–1B yourself, and grafting the same machinery onto an existing open model.

Question 1

Which architecture to build on

Four things matter for this specific project, and the fourth is the one people forget:

  • Modern architecture — so your result isn't obsolete on arrival.
  • Hackable code on GitHub — you're inserting layers, not calling an API.
  • Trainable at 0.2–1B on hardware you can actually get.
  • Known pretraining data and intermediate checkpoints. Forgetting is defined relative to what was learned. Without data transparency you cannot measure your own thesis — you can only measure proxy benchmarks and guess.

Pick: OLMo 2 1B as the backbone. SmolLM2-360M as the prototyping rig.

OLMo 2 is the only genuinely modern architecture in this size class that ships the training code, the full data mix, and hundreds of intermediate checkpoints. For continual-learning research that trio is not a convenience — it's your measurement instrument. Prototype every mechanism on SmolLM2-360M where iteration is measured in hours, then port to OLMo 2 1B for the real numbers.

If you want to be aggressive, interleave a few Gated DeltaNet layers with full attention — that's the pattern Qwen3-Next and Nemotron-H use, and it's the current best answer for long context plus persistent state. It also happens to give you mechanism 9 almost for free, because a gated linear-attention layer is a fast-weight memory. Treat it as an upgrade after the baseline works, not a starting condition.

Question 2 · the design

Don't pick one mechanism. Build a frequency hierarchy.

The single most useful idea across the thirteen papers is Nested Learning's reframe: a Transformer is a two-level system built from the two most extreme update frequencies available — attention at ∞ (recomputed every token) and MLP at 0 (frozen after pretraining). Nothing in between. Every continual-learning method is, in effect, an attempt to manufacture an intermediate frequency by other means.

So manufacture it directly. Four levels, each with its own update rate, its own write rule, and its own paper:

every token L0 · Attention KV Standard context. Nothing to build — this is what you already get. Holds the current document, discarded at the boundary.
token · persists L1 · Fast-weight state Gated DeltaNet layers whose recurrent state M_t = α_t·M_{t−1} + v_t k_tᵀ is carried across documents, not reset. Holds the recent episode. Mechanism 9. Optional; add after the baseline works.
every batch L2 · Sparse memory layer One FFN replaced by a product-key memory, ~512k slots, top-32 lookup. Writes go only to the top-t slots by TF-IDF specificity against a frozen background corpus. Holds new facts. Mechanism 3 — the core of the system.
rare · gated L3 · Backbone FFN Updated infrequently and only alongside a replay mix, with plasticity maintenance running continuously. Holds consolidated knowledge. Mechanisms 1, 11, 13.

Plus a consolidation policy that periodically moves L2 → L3: sample from the memory layer's recently-written slots, generate training data from them, mix with replay, and take a slow update on the backbone. That's the "sleep" step — systems consolidation, in the complementary-learning-systems sense. It's the piece that makes this a system rather than four independent tricks.

Why this is the right shape. Every level maps to a paper you already have, and the failure mode of each is covered by another. L2 forgets fast but L3 holds the consolidated copy. L3 loses plasticity but continual backprop replenishes it. L2 writes interfere but sparsity keeps overlap exponentially small. That mutual coverage is the thing a single mechanism can't give you — and it's the argument the Nested Learning paper makes explicitly about why multi-frequency memory resists forgetting: knowledge dropped by a fast block is still held by a slower one and can be circled back.
This synthesis is mine, not any single paper's. No one has published this exact four-level stack. The individual pieces are each validated — memory layers at 1.3B, continual backprop over 800 tasks, CMS on Llama-3 backbones — but their combination is unproven and the interactions are where the risk lives. Build it incrementally, in the order below, and measure after each addition. If you build all four at once and it underperforms, you will not know which level broke it.
Question 3 · Path A

If you pretrain 0.2–1B yourself

Four things go into the architecture. Everything else is either training policy or a baseline.

Build · mechanism 3 · sparse memory layer

The highest-value item, and the one with the strongest recent evidence: NaturalQuestions F1 dropped 11% versus 89% for full finetuning and 71% for LoRA, at matched acquisition — a Pareto improvement, not a tradeoff. Swap one mid-stack FFN (layer 12 of 24) for a product-key memory. Critically, pretrain with it in place from step 0; the slots need to be populated by the pretraining distribution for the specificity ranking to mean anything later.

I      = topk_indices(K @ q(x), k)     k=32 of N≈512k, product keys
s      = softmax(K[I] @ q(x))
y      = s @ V[I]
out    = (y * silu(x @ W1)) @ W2

# write rule — TF-IDF slot specificity vs a frozen background corpus
             c(i)                |B| + 1
score(i) = ─────────── · log ───────────────────────
           Σ_j c(j)          Σ_b 1[c_b(i) > 0] + 1

# train top-t values only; straight-through mask, top-t changes every forward pass
mem = mem * mask + mem.detach() - (mem * mask).detach()

Start at t=500 for single facts, t≈10_000 for document batches. The ranking is batch-level, so it assumes nothing about task boundaries. Two findings worth carrying over: TF-IDF beats raw frequency and the gap widens as t shrinks; and plain SGD outperformed AdamW for the sparse parameters specifically, with no equivalent gain for dense baselines.

Build · mechanism 11 · plasticity maintenance

Non-negotiable if you train continually. Adam was the worst case tested — plasticity plummets and effective rank collapses; dropout and normalization also made it worse; only continual backprop held flat over 800 tasks. Instrument first (dead_frac, eff_rank, mean_abs_w per group), then add selective reinitialization: replace the lowest-utility fraction ρ of units per layer per step, zero outgoing weights so the function doesn't jump, maturity threshold m before a new unit can be re-selected.

u = η·u_prev + (1−η)·y ;  û = u_prev / (1 − η^age)

At 2048 hidden units, ρ = 1e−4 replaces roughly one unit per layer every five examples. If you want a one-line version first, shrink-and-perturb captures most of the benefit.

Build · mechanism 9 · persistent fast weights

Optional, and strictly after the rest works. Swap a few attention layers for Gated DeltaNet from flash-linear-attention and carry the recurrent state across document boundaries within a training group. Cheap first experiment: take any linear-attention layer, stop resetting its state between documents, and measure backward transfer. That tests the premise for near-zero cost before you commit to a hybrid design.

Scope discipline. Do not build full Hope. The self-referential Titans half — promoting W_k, W_v, W_q, W_η, W_α all to memories that generate their own values — is a large, high-risk build, and the paper's own tables show a plain Transformer still beating Hope 61.4 to 14.8 on 16K multi-key retrieval. Take the multi-frequency idea. Leave the rest.

Policy · mechanisms 1 + 13 · replay and re-warming

Not architecture, but it's the number everything else must beat, and it's probably also just part of your final recipe. A 10% replay mix gave the best overall performance for every model TRACE tested, with positive backward transfer. Add deliberate LR re-warming per stream segment. When you move past pretraining into knowledge injection, upgrade raw replay to logit matching:

L = L_stream + α·‖z′ − h_θ(x′)‖²  + β·CE(y″, f_θ(x″))    α = β = 0.5

Store logits sampled throughout the trajectory via reservoir sampling, not at segment boundaries — that's what separates DER from FDR, and DER++ at buffer 200 beat plain replay at buffer 500.

Question 4 · Path B

Setting the scratch model aside entirely

You asked which options are good without assuming you train from scratch. The answer is meaningfully different, because a strong pretrained backbone unlocks two families that are useless at 1B-from-scratch, and complicates the one that matters most.

The gotcha that will cost you a month if you miss it. Memory layers were pretrained in. The Meta result comes from a model that had the memory layer from step 0, so its million slots carry a meaningful distribution over pretraining data — which is exactly what the IDF term in the ranking measures against. Bolt a randomly-initialized memory layer onto a finished Qwen3 or OLMo and the slots are noise: there is no background access distribution, so specificity ranking is meaningless and the layer just damages the residual stream. Grafting one requires an upcycling phase — replace the FFN, initialize from it, and continue pretraining on enough tokens for the access pattern to stabilize before any of the sparse machinery applies. That's real compute, and it's the strongest single argument for Path A if mechanism 3 is your thesis.

Cheaper substitute if you stay on Path B: apply the same specificity logic to the FFN neurons you already have. Rank existing neurons by activation on the new batch relative to a background corpus, and mask gradients to the top-t. No architecture change, no upcycling phase, and it tests whether the sparsity principle transfers before you pay for the real thing. Weaker than a memory layer — the granularity is thousands of neurons, not a million slots — but it's a two-day experiment instead of a two-month one.

Question 5

What to skip, and why

  • 5 · Hypernetworks. Something must supply the task embedding at inference. Entropy-based inference dropped to 69.48% on split MNIST CL3, and the strong numbers came from adding a replay model or a task classifier — which relocates the problem rather than solving it. Your stream has no task IDs. Steal the idea (regularize in a low-dimensional space instead of million-dimensional weight space); don't build the machinery.
  • 6 · Meta-learning the update rule. The most compute-hungry item on the list, and at 0.2–1B you don't have the budget for a bi-level outer loop. Nested Learning gives you the conceptual payoff — optimizers are associative memories, momentum is a second optimization level — without paying for it.
  • 2 · Gradient projection specifically. GPM gets literally zero forgetting by monotonically consuming free gradient directions: the core gradient space grows and the residual space shrinks with every task. Fine for 10–20 tasks; fatal for an unbounded pretraining stream, and it fights plasticity maintenance directly. Keep the flat-minima half of mechanism 2 — it's nearly free, and it appears as a real term in the survey's generalization bounds. Measure it via the trace of the empirical Fisher.
  • 12 · Bio-inspired, as an implementation. Keep it as the organizing metaphor — the four-level stack above is complementary learning systems, and that framing is load-bearing. But there's no specific bio-inspired algorithm here worth building at this scale. (One exception: if you ever quantize to binary or ternary weights, synaptic metaplasticity becomes nearly free, because the shadow weight is already a consolidation variable. Not applicable to a standard FP backbone.)
Sequence

Build order

A real dependency chain. Each step's output is the next step's measuring stick.

1

The measurement harness

1 week · no model changes · blocks everything else

Pick OLMo 2 1B. Build a forgetting benchmark against its known pretraining data — held-out probes from the actual mix, not generic benchmarks. Add the plasticity probes. Define your stream (what constitutes a "task"). Without this you cannot evaluate a single thing below.

2

The boring baselines

1 week · task arithmetic + replay + RAG

Merge deltas. Run 10% replay with LR re-warming. Stand up a retrieval tier. Now you know what unglamorous methods achieve, which is the bar. A surprising number of projects discover here that they don't need the rest.

3

L2 — the memory layer

3–4 weeks · the core build · prototype on SmolLM2-360M first

Pretrain with a memory layer at mid-stack from step 0. Add TF-IDF sparse writes. This is where the order-of-magnitude result lives if it appears anywhere. Test SGD versus AdamW for the memory parameter group specifically.

4

L3 — plasticity maintenance

1–2 weeks · shrink-and-perturb, then continual backprop

Tune against the step-1 probes. Expect most of the time to go into the utility measure rather than the reinitialization itself.

5

The consolidation policy

2 weeks · the piece that makes it a system

Periodic L2 → L3 transfer: sample recently-written memory slots, synthesize training data, mix with replay, slow update on the backbone. This is the novel contribution — nothing in the thirteen papers does exactly this.

6

L1 — persistent fast weights

optional · highest risk · only if 1–5 are stable

Run the free experiment first: persist a linear-attention state across documents and measure backward transfer. If that moves the needle, invest in a Gated DeltaNet hybrid. If it doesn't, you've saved a month.
